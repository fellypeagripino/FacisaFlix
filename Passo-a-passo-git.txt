Primeiro passo:
- Criar uma conta no github

Segundo passo:
- Instalar o git no computador/notebook (https://git-scm.com/install/)

Terceiro passo:
- Configurar as permissoes do git.

git config --global user.name "Fulano de Tal"
git config --global user.email fulanodetal@exemplo.pt

Quarto passo:
- Criar repositório no github, colocando nome do projeto, descrição e privacidade

Quinta passo:
- Clonagem do repositório com o seguinte comando

git clone https://github.com/fellypeagripino/FacisaFlix.git

Sexto passo:
- Abrir um novo vscode ou intelij na pasta que acobou de aparecer após o comando de git clone

Sétimo passo: (Escrever a carta)
- Adicionar arquivos que irão subir para o repositório dentro do github

git add <nome-arquivo> ou . (Pode ser só o nome do arquivo ou um ponto)
git add Passo-a-passo-git.txt  (Nome do arquivo só irá preparar pra enviar aquele arquivo)
git add . (Quando utilizado o ponto, prepara todos os arquivos alterados/novos/removidos)

Oitavo passo: (Preparar a carta)
- Anotar tudo que está subindo (conhecido como comitar)

git commit -m "Subindo back end e front end do facisa flix"

git commit -m "Título -m "Descrição" (Título do commit vem primeiro, depois a descrição)

Nono passo: (Enviar a carta)
- Enviar o que foi comitado para o github

git push (usar esse primeiro)

git push origin main (Usar esses se algo de errado se tiver no mac iphone)
git push origin master

Passos avançados em equipe

Primeiro passo:
- Criar sua própria branch

git checkout -b nova-branch


Segundo passo:
- Ver as branchs criadas, e ver se foi movido para a branch nova 

git branch -a

Terceiro passo:
-Para transitar entre as branchs já existentes, utiliza-se o seguinte comando

git checkout nome-branch

Quarto passo:
-Pegar as alterações de alguma branch seja ela, main, master, develop, cartao-credito

git pull origin cartao-credito

obs: Não pode ter nada faltando pra subir, ou seja, o git pull só sera feito caso o git add, git commit, tenham sido feito antes
obs2: O git push pode ser feito também após o git commit, porém com algumas ressalvas

Quinto passo:
- Configurar o auto merge para o git pull origin

git config pull.rebase false # merge

Sexto passo:
- Resolver os conflitos, de preferências numa IDE com git lens de extensão

Sétimo passo:
- Após resolver os conflitos (Aceitando alterações, removendo, deixando ambas) 
deve rodar todos os comandos padrões de push, ou seja, git add . , git commit -m "", git push origin
